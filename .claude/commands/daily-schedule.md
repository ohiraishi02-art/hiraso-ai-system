# 朝の工程表を作成する

毎朝の工程表を作成するスキル。以下の手順で実行する：

## 実行手順

1. **予定の収集**
   - Google Calendarから今日の予定を取得（MCP接続済みの場合）
   - 接続されていない場合は、ユーザーに今日の予定を口頭で確認

2. **タスクの収集**
   - GitHub Issueから進行中・未着手のタスクを取得（`gh` が利用可能な場合）
   - `DAILY.md` を読み込み、昨日の未完了タスクを確認
   - `03_projects/` 配下を確認し、期限の近いタスクを把握

3. **タスクの分類**
   以下の2軸で分類する：
   - **緊急度×重要度**（アイゼンハワー・マトリクス）
     - A: 緊急かつ重要（即対応）
     - B: 重要だが緊急ではない（計画的に）
     - C: 緊急だが重要ではない（委任・簡略化）
     - D: どちらでもない（後回し or 削除）
   - **認知負荷**（高/中/低）
     - 高: 戦略立案、執筆、複雑な分析
     - 中: ミーティング、レビュー、リサーチ
     - 低: メール返信、事務作業、ルーティン

4. **工程表の生成**
   - 午前に認知負荷の高いタスクを配置
   - 15分刻みの工程表を作成
   - 休憩・バッファ時間を適切に挿入
   - プライベートの予定も含めて一日全体を設計

5. **出力**
   - `DAILY.md` に本日の日付セクションを追加し、工程表を書き込む
   - ユーザーに工程表を提示し、調整の要望を確認

## 出力フォーマット

```markdown
### YYYY-MM-DD（曜日）

#### 本日のサマリー
- 重要タスク: X件
- 会議: X件
- 推定作業時間: X時間

#### 工程表
| 時間帯 | タスク | 優先度 | 認知負荷 | 状態 |
|:-------|:------|:-------|:---------|:-----|
| 09:00-09:30 | メール・Slack確認 | C | 低 | ⬜ |
| ... | ... | ... | ... | ... |

#### 持ち越しタスク（昨日から）
- [ ] ...

#### メモ
```
